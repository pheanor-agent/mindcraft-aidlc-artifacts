## How to use this index

1. Read `requirements-evolution.md` before rewriting requirements.
2. Read the original requirement and constraint files before reading review conclusions.
3. Treat submitted consolidated revisions as proposals until their workspace paths and provenance are verified.
4. Use `rewrite-checklist.md` as a preflight checklist for a new Requirements draft.
5. Do not copy historical conclusions into product runtime Knowledge automatically.

## Status vocabulary

- **Draft**: written but not approved.
- **Review**: consistency/provenance/acceptance analysis completed or pending.
- **Approval requested**: human decision required; no Construction authorization implied.
- **Approved**: only use when an explicit human approval record exists.
- **Historical**: retained for reasoning; not automatically authoritative.

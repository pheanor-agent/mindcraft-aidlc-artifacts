Windows 실행 환경 기능·안정성 검증

대상: v0.1.0-windows-preview.20260907.2의 실제 MindCraft.exe, 번들 Node 22.19.0. Windows x64에서 별도 한글·공백 workspace, CLI 및 ConPTY TTY로 실행했다. 제품 파일은 수정하지 않았다. 결론: 기본 저장·종료·복구는 동작하지만 정상 설정부터 Run/승인/명령 실행까지의 기능 흐름은 출시 차단 결함이 있어 통과하지 못했다.

조건과 범위

  • 외부 자격증명을 제거하고 PATH를 Windows System32로 제한했다. 개발용 Node가 없는 휴대형 실행 환경을 재현했다.
  • 기본 조건에서 --cli --mock, setup mock deterministic, task, run을 실행했다.
  • 기본 조건의 모델 불일치를 확인한 다음, 진단용으로만 MINDCRAFT_PROVIDER=mock, MINDCRAFT_MODEL=deterministic을 명시해 후속 기능을 확인했다. 이 조건의 성공은 기본 설정 문제 해결을 의미하지 않는다.
  • 승인 시험에서는 격리 workspace에 단순 Node 테스트 fixture를 만들었다. 외부 API·사용자 프로젝트 파일에는 접근하지 않았다.

발견한 결함

F1 — 설정한 Model과 실행 Model 불일치 (높음)

재현: 기본 환경에서 --mock → setup mock deterministic → task ... → run inspect.

결과: error: Airouter model is not registered. history의 routing에는 mock-deterministic이 선택돼 있지만 실제 getSelectedModel()은 별도 modelSelection의 기본 Airouter를 참조한다. 설정/preflight 준비 상태가 실제 실행을 보장하지 못한다. 진단 환경변수 지정 시에만 다음 단계로 진행했다.

F2 — Run 중 승인 목록 조회 불가 (높음)

진단 조건에서 Run이 승인 대기에 들어간 뒤 approvals를 입력해도 응답하지 않는다. CLI CommandQueue가 진행 중인 run 뒤에 조회를 대기시킨다. 화면에는 event=tool_decision만 나오며 승인 ID가 없다. journal에서 ID를 읽어 우선 처리되는 reject/approve를 보내자 실행이 풀렸고, 그 뒤에야 대기 중인 approvals가 No pending approvals를 출력했다. 일반 사용자 흐름으로는 승인 진행이 막힌다.

F3 — 번들 Node가 하위 명령 실행에 사용되지 않음 (높음)

PATH에서 개발용 Node를 제외하고 mock의 allowlist 명령을 승인하면 spawn node ENOENT. launcher 자체는 번들 Node로 시작하지만 하위 명령의 node 탐색은 실패한다. 실행파일의 휴대형 환경에서 승인된 작업 수행이 불가능하다.

F4 — 명령 실패인데 Run은 completed (상태 표현 검토 필요)

F3의 command 결과에 code=null/error가 있는데 run=completed와 completed history가 남는다. 세션 종료와 작업 성공을 구분해야 한다. mock 본문은 테스트 성공을 주장하지 않지만 상위 상태는 실패를 드러내지 않는다.

시험 도구의 오류와 정정

원시 기록은 실패한 시험 시도도 보존한다. 첫 run 대기 timeout은 F1 오류 문자열을 기다리지 않은 harness 오류였다. 초기 동시 실행 검사는 시작 완료 전에 판정했고, 보완 시험에서 실제 lock 거절을 확인했다. 초기 강제 종료는 제한 환경의 Access denied로 실행되지 않았으며 제품 복구 실패로 분류하지 않았다. 권한을 갖춘 별도 시험에서 직접 생성한 프로세스 트리 종료와 복구가 통과했다. 옵션/config의 조기 code 검사 false는 비동기 종료 관측 시점 문제이며, 최종 세션 기록의 2/1을 기준으로 판정했다. 따라서 원시 results.json의 단순 pass 합계를 제품 통과율로 사용하지 않는다.

제한 및 다음 작업

실제 LLM/네트워크 장애, 장시간 soak·메모리 누수 정량 평가, Windows Terminal 앱의 시각 품질 및 한국어 IME, 설치/업데이트는 미검증이다. 기존 소스 회귀 141/155 및 실패 14건은 이번에 다시 실행하지 않았으며 해결됐다고 주장하지 않는다. F1–F3 수정 후 기본 환경에서 승인·실행 전체 흐름을 다시 검증해야 한다. 현재 릴리즈의 안정성 승인이나 새로운 실행파일 릴리즈는 하지 않는다.

원시 세션 로그와 재현 harness는 runtime-stability 증거에 보존한다. DDT에 실제 JOB 워크플로우의 후속 검증 산출물로 접수하도록 직접 요청한다.

DDT 실제 워크플로우 접수 확인

DDT agent 종료 코드 0, 원격 산출물 33개 수신. 기존 정확한 JOB 폴더의 phase-record, follow-up, external-result, artifacts-manifest, audit에 이번 검증을 추가했으며 별도 재조회로 확인했다. DDT 접수 결과와 JOB 실제 파일 snapshot을 보존한다. 기존 번호 충돌과 canonical gate 누락은 미해결이며 상태는 request/in_progress로 유지된다.

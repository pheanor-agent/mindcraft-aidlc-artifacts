MindCraft ToDo 및 자체 심사

Historical note: 이 문서는 2026-09-03 이전의 개념 검토 기록이다. 당시의 AI-DLC workspace 표현은 현재 기준에서 폐기되었다. AI-DLC는 MindCraft 런타임이 아니라 MindCraft 개발·검증에 사용한 외부 방법론이다. 이 문서는 현재 SSOT가 아니다.

자체 심사 운영 규칙

  • milestone 또는 데모 직전에 이 문서를 갱신한다.
  • 점수는 증거가 있을 때만 부여한다.
  • 각 개선 항목에는 담당, 검증 방법, 완료 조건을 기록한다.
  • 심사 기준별 최고점 합계는 100점이다.

현재 자체 심사 초안

아래 점수는 공식 심사 결과가 아니라, 현재 구현 및 문서에 근거한 내부 초안입니다. Node.js/npm이 없는 현재 환경에서는 실행 검증을 새로 수행하지 못했으므로, 실행 관련 항목은 보수적으로 평가합니다.

기준 배점 현재 예상 근거 / 부족한 점
AI-DLC 사용 충실성 25 0 실제 개발팀의 대표 workflow와 AI 활용 효과를 측정한 증거가 아직 부족함
문제 정의 및 해결 20 0 문제 정의는 문서화했지만 사용자 검증과 전후 비교 자료가 부족함
창의성 15 0 durable workflow, Knowledge approval, tool safety 조합은 있으나 차별점 메시지 정리가 필요함
완성도 15 0 핵심 코드와 배포 문서는 있으나 현재 환경에서 build/test 재실행이 막힘
사용성 15 0 CLI 명령은 정의되어 있으나 신규 사용자의 실제 사용 관찰이 부족함
유지보수성 및 보안 10 0 scope, fail-closed, redaction 설계는 있으나 보안 테스트와 운영 문서 보강 필요
합계 100 0 실행 가능한 증거 확보 후 재평가

    • 완료 조건: Task 공유, 실행 결과 확인, 검토/승인, 지식 재사용을 한 번의 시나리오로 시연

  • 관련도 기반 LLM Wiki TUI 구현

    • 방향: Knowledge 목록 → 검색/필터 → 관련도 순 정렬 → 상세/연결 Run 보기 → 승인/거절

    • 완료 조건: 첫 화면에서 active Task, running Run, 최근 Knowledge, 추천 다음 행동을 확인

  • AI-DLC 효과 측정 추가

    • 측정 후보: 소요 시간, prompt/토큰 사용량, 반복 작업 횟수, 누락된 위험 항목 수

P2 — 바이브 코딩 지원형 자동 개입 및 Routing

현재 핵심 협업 workflow와 LLM Wiki/TUI 완성 이후 검토하는 최하위 우선순위 항목입니다. 목표는 사용자의 자유로운 바이브 코딩 흐름을 강제로 바꾸지 않으면서, 필요할 때만 시스템이 개입해 효율을 높이는 것입니다.

  • 바이브 코딩 맥락 감지

    • 자유 형식의 사용자 요청과 현재 작업 상태에서 의도, 작업 유형, 반복 패턴, 필요한 도구를 추정
    • 담당: TBD
    • 검증 방법: 사용자가 task/run 명령 없이 코드 작성·수정·리뷰 요청을 자연어로 입력
    • 완료 조건: 감지된 의도와 개입 필요 여부를 사용자에게 설명하고, 오탐 시 무개입으로 유지

  • 자연어 요청 기반 Task 자동 생성 또는 기존 Task 연결

    • 예: 사용자가 릴리스 위험도를 분석해줘라고 입력하면 적절한 Task/목표를 제안
    • 담당: TBD
    • 검증 방법: 명시적인 task 명령 없이 자연어 요청 입력
    • 완료 조건: 자동 생성 전 사용자 확인 또는 기존 Task 연결 확인

  • 상황 기반 CLI/Provider/Model 연결 제안

    • 예: 코드 수정은 coding CLI, 문서화는 documentation workflow, 릴리스 분석은 risk scoring workflow로 연결 제안
    • 담당: TBD
    • 검증 방법: 작업 유형별 연결 대상, 이유, 예상 효과 표시
    • 완료 조건: 사용자가 연결 결과를 확인·변경할 수 있고, 미지원 CLI/Provider는 자동 실행하지 않음

  • 자연어 요청 기반 Run 자동 실행

    • 담당: TBD
    • 검증 방법: 사용자가 run 명령을 생략한 요청 처리
    • 완료 조건: 실행 전 대상 Task, 사용 CLI/Model, Knowledge context, 위험 작업 여부를 요약하고 사용자 승인을 받은 뒤 실행

  • 비침해형 개입 및 안전장치

    • 담당: TBD
    • 검증 방법: 모호한 요청, 반복 작업, Provider 미지원, credential 미설정, 위험한 tool 요청 테스트
    • 완료 조건: 필요한 순간에만 제안하고, 모호하거나 위험하면 확인 질문 또는 안전한 fallback으로 전환하며 사용자가 제안을 무시할 수 있음
